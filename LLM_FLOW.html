Review nhận được gì?


Điều cần nhớ
Dùng lại cache không phải gắn nhãn mới; kiểm tra model, prompt và ID.






Quan trọng: Đây là luồng sau khi bước chuẩn bị đã đạt. Thiếu model/key, input rỗng/trùng ID hoặc cache JSONL hỏng có thể dừng trước vòng review; không bảo đảm luôn có output/report. Sơ đồ phản ánh các nhánh chính. Thực tế còn có retry, dừng quota, thiếu key, JSON sai schema và lỗi ghi đĩa. Cache thành công lưu riêng; output cuối có cả review lỗi. Không chuyển status=error thành nhãn sentiment.






02. File nào chịu trách nhiệm bước nào?




🎛️ src/llm.py
CLI và API tương thích để chạy LLM: đọc tham số --input, --output, --skip-llm, gọi runner. Lệnh: python run_tv4.py llm --help.


📐 src/llm_contract.py
Quy tắc: nhãn nào hợp lệ, trạng thái nào hợp lệ, tạo khóa cache dựa trên dữ liệu + cấu hình. Không gửi API.


🌐 src/gemini_client.py
Giao tiếp mạng: tạo payload, gửi Gemini, timeout/retry, chuẩn hóa lỗi HTTP. Không đọc nhãn người.


⚙️ src/llm_runner.py
Điều phối: lọc QA, tìm cache, gọi client nếu cần, kiểm tra JSON, ghi kết quả từng review và báo cáo cuối.


🔍 src/cache_audit.py
Luồng phụ offline: chạy python -m src.cache_audit --help; kiểm tra cache với QA/marking và tạo template nhãn tay. Số dòng theo marking, không tự bảo đảm 100.


📁 Phụ thuộc trong cùng repository
src/common.py cung cấp I/O; audit import parser marking của src/prepare.py; configs/toronto.json lưu config LLM. Lấy đủ các file từ nhánh gmnh.
📊 src/tv4_evaluation.py
So sánh sentiment với nhãn người: python -m src.tv4_evaluation --help. Router đã hỗ trợ python run_tv4.py evaluate và python run_tv4.py cache_audit; lệnh module vẫn dùng được.

03. Đầu vào, dữ liệu trung gian và đầu ra




INPUT · reviews_after_qa.csv
snapshot_date,review_id,listing_id,comments,split,text_valid,listing_match
2026-06-15,DEMO-001,LIST-001,"Clean apartment",analysis,true,true
Giữ review ID dưới dạng chuỗi, không ép sang float. Có thể có thêm cờ QA.


MODEL RESPONSE · JSON schema v1
{
  "sentiment": "positive",
  "aspects": [{"aspect":"cleanliness","polarity":"positive"}],
  "language": "en",
  "status": "ok",
  "error": null
}
Chỉ năm khóa này được chấp nhận từ mô hình. Sau validate, runner bổ sung ID, fingerprint, provenance.


OUTPUT · *.jsonl
{
  "review_id": "DEMO-001",
  "sentiment": "positive",
  "status": "ok",
  "from_cache": true,
  "api_requests": 0,
  "cache_key": "..."
}
Ví dụ rút gọn. API mới có ID/model/hash/thời gian và metadata. Cache hit giữ metadata bản cache, nên cache cũ/demo có thể thiếu trường tùy chọn.


REPORT · *.jsonl.run.json
{
  "rows": 3,
  "cache_hits": 1,
  "api_requests": 0,
  "status_counts": {"ok": 1, "error": 2},
  "skip_llm": true
}
Ví dụ rút gọn của offline demo; chỉ ghi sau khi batch hoàn thành. Khi preflight đạt, report cũ được xóa trước batch mới; nếu bị ngắt thì chưa có report hoàn tất. Preflight thất bại giữ nguyên kết quả cũ.




Ý nghĩa các trạng thái


Trạng tháiÝ nghĩaTiếp theo

05. Trước khi chạy API thật
    

  • Đừng gửi API key lên GitHub/chat. Chỉ đặt $env:GEMINI_API_KEY trong PowerShell ở máy cá nhân.
    • 

  • Không gọi thử bằng --refresh khi chưa rõ cache: nó bỏ qua kết quả cũ và có thể tiêu quota.
    • 

  • Kiểm tra GEMINI_MODEL khớp mô hình mong muốn; đổi model/prompt/schema/text sẽ tạo fingerprint khác.
    • 

  • Đặt output riêng, không ghi đè cache, input CSV hoặc file kết quả đang dùng.
    • 

  • Không chạy hai writer đồng thời cùng cache/output. Mất điện đột ngột vẫn có thể để dòng JSONL cuối dang dở.
    • 

  • Smoke dùng cache riêng trước khi gọi; tránh để review giả lập vào cache nhóm. Batch thật truyền --input, --output và hạn mức rõ ràng theo README.
    • 

  • Cache nhận từ nguồn khác: writer bổ sung newline khi cần append; cache-only giữ nguyên byte. JSONL đã hỏng vẫn bị từ chối, không tự phục hồi nội dung.
    • 

  • CLI trả 0 không có nghĩa mọi review đều ok. Đọc status_counts, error_counts, timestamp và số dòng. Report/token metadata không phải xác nhận tính phí từ server.
    • 

  • QA và nhãn người là hai việc khác nhau: QA xác định review đủ điều kiện; manual test mới là gold label để tính accuracy/F1.
    • 

Trang HTML này chỉ để giải thích, không phải dashboard kết nối dữ liệu thật hay giao diện điều khiển Gemini. Để chạy thật, xem llm_readme.md và run_tv4.py llm --help.
